设计一个 API

在 Kubernetes 中设计 API 有若干规则。即：所有序列化字段_必须_为 camelCase，因此用 JSON 结构体标签指定。也可用 omitempty 标记空值时省略序列化。

字段可以使用大部分原始类型。数字是一个例外：出于API兼容性考虑，我们接受三种数字形式：int32 和 int64 用于整数，resource.Quantity 用于小数。

Hold up, what is a Quantity?

数量是对十进制数字的一种特殊表示法，它具有明确固定的表示方式，使其在不同机器之间更具可移植性。您可能在Kubernetes中为pod指定资源请求和限制时注意到了它们。

它们在概念上与浮点数相似：具有有效数字、基数和指数。它们的可序列化和可读格式使用整数和后缀来指定值，方式与我们描述计算机存储的方式类似。

例如，值 2m 在十进制表示中代表 0.002。 2Ki 在十进制中表示 2048，而 2K 在十进制中表示 2000。如果我们想指定小数，我们可以切换到一个后缀，使我们能够使用整数：2.5 表示为 2500m。

支持两种进制：10 进制和 2 进制（分别称为十进制和二进制）。十进制使用“常规“国际单位制后缀表示（例如 M 和 K），而二进制使用“兆比特“（mebi）表示法（例如 Mi 和 Ki）。可以参考 兆字节与兆比特 的区别。

我们使用的另一种特殊类型是 metav1.Time。它的功能与 time.Time 相同，但具有固定的可移植序列化格式。

先看 spec。如前所述，spec 保存_期望状态_，因此控制器的所有“输入”都放这里。

从根本上说，CronJob 需要以下几部分：

  • 一个调度表达式（CronJob 中的 cron）
  • 要运行的 Job 模板（CronJob 中的 job）

还需要一些额外项，让用户更省心：

  • 启动 Job 的截止时间（错过则等到下次调度）
  • 若多个 Job 本应同时运行该怎么办（等待？停掉旧的？都跑？）
  • 暂停 CronJob 运行的方式，以防出问题
  • 旧 Job 历史的保留限制

请记住，由于我们从不读取自己的 status，需要用其他方式跟踪 Job 是否已运行。我们可以至少用一个旧 Job 来做到这一点。

我们将使用多个标记（// +comment）指定额外元数据。生成 CRD 清单时，controller-tools 会使用它们。稍后会看到，controller-tools 还会用 GoDoc 形成字段描述。

// CronJobSpec 定义 CronJob 的期望状态
type CronJobSpec struct {
	// Cron 格式的调度表达式，参见 https://en.wikipedia.org/wiki/Cron.
	// +kubebuilder:validation:MinLength=0
	// +required
	Schedule string `json:"schedule"`

	// startingDeadlineSeconds 定义若错过计划时间则启动 Job 的秒数截止
	// time for any reason.  Missed jobs executions will be counted as failed ones.
	// +optional
	// +kubebuilder:validation:Minimum=0
	StartingDeadlineSeconds *int64 `json:"startingDeadlineSeconds,omitempty"`

	// concurrencyPolicy 指定如何处理 Job 的并发执行。
	// 有效值为：
	// - "Allow"（默认）：允许 CronJob 并发运行；
	// - "Forbid"：禁止并发，若上次运行未结束则跳过下次；
	// - "Replace"：取消当前运行的 Job 并用新 Job 替换
	// +optional
	// +kubebuilder:default:=Allow
	ConcurrencyPolicy ConcurrencyPolicy `json:"concurrencyPolicy,omitempty"`

	// suspend 告诉控制器暂停后续执行，它
	// 不适用于已开始的执行。默认为 false。
	// +optional
	Suspend *bool `json:"suspend,omitempty"`

	// jobTemplate 定义执行 CronJob 时将创建的 Job。
	// +required
	JobTemplate batchv1.JobTemplateSpec `json:"jobTemplate"`

	// successfulJobsHistoryLimit 定义要保留的成功完成 Job 数量。
	// 使用指针以区分显式零值与未指定。
	// +optional
	// +kubebuilder:validation:Minimum=0
	SuccessfulJobsHistoryLimit *int32 `json:"successfulJobsHistoryLimit,omitempty"`

	// failedJobsHistoryLimit 定义要保留的失败完成 Job 数量。
	// 使用指针以区分显式零值与未指定。
	// +optional
	// +kubebuilder:validation:Minimum=0
	FailedJobsHistoryLimit *int32 `json:"failedJobsHistoryLimit,omitempty"`
}

我们定义自定义类型来保存并发策略。底层实际只是字符串，但该类型能提供额外文档，并允许把校验附在类型而非字段上，使校验更易复用。

// ConcurrencyPolicy 描述如何处理 Job。
// 下列并发策略只能指定其一。
// 若未指定下列任一策略，则默认
// 为 AllowConcurrent。
// +kubebuilder:validation:Enum=Allow;Forbid;Replace
type ConcurrencyPolicy string

const (
	// AllowConcurrent 允许 CronJob 并发运行。
	AllowConcurrent ConcurrencyPolicy = "Allow"

	// ForbidConcurrent 禁止并发运行；若上次
	// 尚未结束则跳过下次运行。
	ForbidConcurrent ConcurrencyPolicy = "Forbid"

	// ReplaceConcurrent 取消当前运行的 Job 并用新 Job 替换。
	ReplaceConcurrent ConcurrencyPolicy = "Replace"
)

接下来设计 status，保存观测状态，包含希望用户或其他控制器能轻松获取的信息。

我们将保留活动运行 Job 的列表，以及成功运行 Job 的最后时间。注意我们使用 metav1.Time 而非 time.Time 以获得稳定序列化，如前所述。

// CronJobStatus 定义 CronJob 的观测状态.
type CronJobStatus struct {
	// 插入额外的状态字段 - 定义集群的观察状态
	// 重要：在修改此文件后，请运行 "make" 以重新生成代码

	// active 定义指向当前运行 Job 的指针列表。
	// +optional
	// +listType=atomic
	// +kubebuilder:validation:MinItems=1
	// +kubebuilder:validation:MaxItems=10
	Active []corev1.ObjectReference `json:"active,omitempty"`

	// lastScheduleTime 定义 Job 上次成功调度的时间。
	// +optional
	LastScheduleTime *metav1.Time `json:"lastScheduleTime,omitempty"`

	// Kubernetes API 约定参见：
	// https://github.com/kubernetes/community/blob/master/contributors/devel/sig-architecture/api-conventions.md#typical-status-properties

	// conditions 表示 CronJob 资源的当前状态。
	// 每个 condition 有唯一类型，反映资源某一方面的状态。
	//
	// Standard condition types include:
	// - "Available": the resource is fully functional
	// - "Progressing": the resource is being created or updated
	// - "Degraded": the resource failed to reach or maintain its desired state
	//
	// The status of each condition is one of True, False, or Unknown.
	// +listType=map
	// +listMapKey=type
	// +optional
	Conditions []metav1.Condition `json:"conditions,omitempty"`
}
