使用（alpha update）更新你的项目

概述

kubebuilder alpha update 使用三方 Git 合并将项目脚手架升级到更新的 Kubebuilder 发行版。它为旧版与新版重建干净脚手架，将当前代码合并到新脚手架，并给出可审查的输出分支。它处理繁重工作，让你专注于审查与解决冲突，而非重新应用代码。

默认情况下，最终结果会在专用输出分支上压缩为单个提交。若希望保留完整历史（不 squash），请使用 --show-commits。

Automate this process

你可以使用 AutoUpdate 插件 减轻保持项目最新的负担；当有新的 Kubebuilder 版本发布时，它会通过定时工作流自动运行 kubebuilder alpha update。

何时使用它

在以下情况使用此命令：

  • 希望迁移到更新的 Kubebuilder 版本或插件布局
  • 希望在单独分支上审查脚手架变更
  • 希望专注于解决合并冲突（而非重新应用自定义代码）

它是如何工作的

你告知工具新版本以及项目所在分支。它会重建两套脚手架，用三方合并将你的代码合并到新脚手架中，并给出可安全审查与合并的输出分支。你可以选择单个干净提交、完整历史，或自动推送到远程。

步骤 1：Detect versions

  • 它会查看你的 PROJECT 文件或你传入的标志。
  • 通过读取 PROJECT 文件中的 cliVersion 字段（若可用）确定你来自哪个旧版本。
  • 确定你想要的新版本（默认为最新发行版）。
  • 选择包含当前代码的分支（默认为 main）。

步骤 2：Create scaffolds

该命令会创建三个临时分支：

  • 祖先：来自旧版本的干净项目脚手架。
  • 原始：你当前代码的快照。
  • 升级：来自新版本的干净脚手架。

步骤 3：Do a 3-way merge

  • 使用 Git 的三方合并将原始（你的代码）合并到升级（新脚手架）中。
  • 在引入上游变更的同时保留你的自定义内容。
  • 如果发生冲突：
    • 默认 → 停止并让你手动解决。
    • 使用 --force → 即使有冲突标记也继续并提交。（适合自动化）
  • 运行 make manifests generate fmt vet lint-fix 进行整理。

步骤 4：Write the output branch

  • 默认情况下，所有内容会在安全输出分支上压缩为单个提交：kubebuilder-update-from-<from-version>-to-<to-version>。
  • 你可以更改行为：
    • --show-commits：保留完整历史。
    • --restore-path：在压缩模式下，从基线分支恢复特定文件（如 CI 配置）。
    • --output-branch：选择自定义分支名。
    • --merge-message：自定义干净合并时的提交信息。
    • --conflict-message：自定义发生冲突时的提交信息。
    • --push：自动将结果推送到 origin。
    • --git-config: sets git configurations.
    • --open-gh-issue：创建带有清单与对比链接的 GitHub issue（需要 gh）。

步骤 5：Cleanup

  • 输出分支就绪后，所有临时工作分支将被删除。
  • 最终得到一个干净分支，可测试、审查并合并回主分支。

如何使用（命令）

在项目根目录运行：

kubebuilder alpha update

固定版本与基线分支：

kubebuilder alpha update \
--from-version v4.5.2 \
--to-version   v4.6.0 \
--from-branch  main

适合自动化（即使有冲突也继续）：

kubebuilder alpha update --force

保留完整历史而非压缩：

kubebuilder alpha update --from-version v4.5.0 --to-version v4.7.0 --force --show-commits

默认压缩，但保留基线分支的 CI/工作流：

kubebuilder alpha update --force \
--restore-path .github/workflows \
--restore-path docs

使用自定义输出分支名：

kubebuilder alpha update --force \
--output-branch upgrade/kb-to-v4.7.0

运行更新并将结果推送到 origin：

kubebuilder alpha update --from-version v4.6.0 --to-version v4.7.0 --force --push

自定义提交信息：

kubebuilder alpha update --force \
--merge-message "chore: upgrade kubebuilder scaffold" \
--conflict-message "chore: upgrade with conflicts - manual review needed"

处理冲突（--force 与默认）

使用 --force 时，即使有冲突 Git 也会完成合并。提交将包含如下标记：

<<<<<<< HEAD
Your changes
=======
Incoming changes
>>>>>>> (original)

这允许你在 CI 或 cron 任务中运行该命令而无需人工干预。

  • 不使用 --force：命令停在 merge 分支并打印指引；不创建提交。
  • 使用 --force：合并会被提交（merge 或 output 分支）并包含标记。

修复冲突后，始终运行：

make manifests generate fmt vet lint-fix
# or
make all

与 GitHub Issues 一起使用（--open-gh-issue）

传入 --open-gh-issue 让命令在仓库中创建 GitHub Issue 以协助更新。

Automation

这能与自动化良好集成。autoupdate.kubebuilder.io/v1-alpha 插件可生成按计划（例如每周）运行该命令的 GitHub Actions 工作流。当有新的 Kubebuilder 版本可用时，它会打开带有对比链接的 Issue，便于你创建 PR 并审查。

仅在运行期间更改额外 Git 配置（不修改你的 ~/.gitconfig）

默认情况下，kubebuilder alpha update 会应用安全的 Git 配置：merge.renameLimit=999999、diff.renameLimit=999999、merge.conflictStyle=merge。你可以追加更多配置，或禁用它们。

  • 在默认值之上追加更多
kubebuilder alpha update \
  --git-config rerere.enabled=true
  • 完全禁用默认值
kubebuilder alpha update --git-config disable
  • 禁用默认值并设置你自己的
kubebuilder alpha update \
  --git-config disable \
  --git-config rerere.enabled=true

You might need to upgrade your project first

此命令底层使用 kubebuilder alpha generate。我们支持用 v4.5.0+ 创建的项目。若项目更旧，请先运行一次 kubebuilder alpha generate 以现代化脚手架。之后即可用 kubebuilder alpha update 进行后续升级。

使用 Kubebuilder v4.6.0+ 创建的项目会在 PROJECT 文件中包含 cliVersion。该命令使用该值选择正确的 CLI 以重新生成脚手架。

旗帜

Flag描述
--conflict-message存在冲突时合并的自定义提交信息。默认为 :warning: chore(kubebuilder): update scaffold (manual conflict resolution) <from> -> <to>。
--force即使发生合并冲突也继续。冲突文件会带着冲突标记被提交（适合 CI/cron）。
--from-branch保存当前项目代码的 Git 分支。默认为 main。
--from-version要更新自的 Kubebuilder 发行版（例如 v4.6.0）。未设置时尽可能从 PROJECT 文件读取。
--git-config可重复。以 -c key=value 传入每次调用的 Git 配置。默认（若省略）：-c merge.renameLimit=999999 -c diff.renameLimit=999999。你的配置会叠加应用。要禁用默认配置，请包含 --git-config disable。
--merge-message成功合并（无冲突）的自定义提交信息。默认为 chore(kubebuilder): update scaffold <from> -> <to>。
--open-gh-issue更新完成后创建带有预填清单与对比链接的 GitHub issue（需要 gh）。
--output-branch输出分支名称。默认：kubebuilder-update-from-<from-version>-to-<to-version>。
--push更新完成后将输出分支推送到 origin 远程。
--restore-path可重复。压缩时要从基础分支保留的路径（例如 .github/workflows）。与 --show-commits 不兼容。
--show-commits保留完整历史（不压缩）。与 --restore-path 不兼容。
--to-version要更新到的 Kubebuilder 发行版（例如 v4.7.0）。未设置时默认为最新可用发行版。
-h, --help显示此命令的帮助。
