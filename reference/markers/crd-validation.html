CRD 验证

这些标记会修改 CRD 验证模式在其修改的类型和字段上的生成方式。每个标记大致对应于一个 OpenAPI/JSON 模式选项。

请参阅 生成 CRD 以获取示例。

Understanding Marker Grouping in Documentation

某些标记可能看起来重复。然而，这些标记是根据它们的使用上下文进行分组的——例如字段、类型或数组。例如，一个像 +kubebuilder:validation:Enum 的标记可以应用于单个字段或数组项，这种灵活性在文档中有所体现。

这种分组确保了清晰性，展示了同一个标记如何可以被用于不同的目的。

Schema & Validation

自定义资源使用生成的 OpenAPI v3 schema 进行验证，且必须遵守 Kubernetes structural schema 规则。API 服务器仅强制执行可在 CRD schema 中表示的字段类型与约束。

数值类型受 Kubernetes CRD OpenAPI v3 schema 兼容性 约束。实践中优先使用能干净映射到受支持 OpenAPI 格式的 Go 类型（例如整数用 int32 和 int64）。需要类小数表示的值请使用 resource.Quantity。

使用 Kubebuilder 校验 markers 声明额外约束——例如最小值与最大值、长度限制、模式、枚举以及 list 或 map 规则——以便它们反映在生成的 CRD 中并在运行时校验。

for array items marks a field as requiring a value for which a given

表达式求值为 true。

此标记可重复以指定多个表达式，所有这些表达式都必须求值为 true。

CEL 表达式可使用：self（当前值）和 oldSelf（先前值；仅在更新时，创建时为 null）。规则作用域为其在 schema 中出现的位置；self 即为该值。

Examples:

// Basic field validation using self
// +kubebuilder:validation:XValidation:rule=&#34;self.minReplicas &lt;= self.replicas &amp;&amp; self.replicas &lt;= self.maxReplicas&#34;,message=&#34;replicas must be between minReplicas and maxReplicas&#34;

// Validation with custom reason
// +kubebuilder:validation:XValidation:rule=&#34;self.x &lt;= self.maxX&#34;,message=&#34;x cannot be greater than maxX&#34;,reason=&#34;FieldValueInvalid&#34;

// Immutability check using oldSelf (e.g. on a field so self/oldSelf are that field&#39;s value)
// +kubebuilder:validation:XValidation:rule=&#34;self == oldSelf&#34;,message=&#34;field is immutable&#34;

// Validation with field path for better error reporting
// +kubebuilder:validation:XValidation:rule=&#34;self &gt;= 1&#34;,message=&#34;value must be at least 1&#34;,fieldPath=&#34;.spec.replicas&#34;
fieldPath
string
is the path to the field that failed validation (for clearer error messages).

示例：FieldPath=“.spec.replicas”

message
string
is the text shown when validation fails.

若未设置，默认为 “failed rule: {Rule}”。不得包含换行。API 服务器有长度限制（例如 256 个字符）。完整细节见 k8s.io/apiextensions-apiserver 中的 ValidationRule。示例：Message=“replicas must be between minReplicas and maxReplicas”

messageExpression
string
is a CEL expression that returns the message shown when validation fails.

可以设置 Message 或 MessageExpression，不能同时设置。MessageExpression 必须返回字符串。若两者都设置，使用 MessageExpression。若都未设置，使用默认消息。表达式可使用与 Rule 相同的变量（例如 self、oldSelf）。结果不得包含换行，并受与 Message 相同的消息长度限制。示例：MessageExpression=“’replicas must be between ’ + string(self.minReplicas) + ’ and ’ + string(self.maxReplicas)”

optionalOldSelf
bool
OptionalOldSelf, when true, runs the rule on create and on update (even when there is no old value).

为 true 时，oldSelf 可能缺失：使用 oldSelf.hasValue() 检查，并用 oldSelf.value() 取值。规则始终运行；使用 oldSelf 前必须在规则中检查 oldSelf.hasValue()。仅当规则使用 oldSelf 时可设置。参见 k8s.io/apiextensions-apiserver 中的 ValidationRule。示例：OptionalOldSelf=true

reason
string
is a short code for why validation failed, returned to API callers.

支持的值：“FieldValueInvalid”、“FieldValueForbidden”、“FieldValueRequired”、“FieldValueDuplicate”。未设置时默认为 “FieldValueInvalid”。示例：Reason=“FieldValueInvalid”

rule
string
is the CEL expression that must evaluate to true.

作用域为该 XValidation 在 schema 中的位置；self 即为该值。示例：Rule=“self.minReplicas <= self.replicas && self.replicas <= self.maxReplicas”
