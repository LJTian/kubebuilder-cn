为 Kubebuilder 创建外部插件

概述

Kubebuilder 的功能可以通过外部插件进行扩展。这些插件是可执行文件（可以用任何语言编写），遵循 Kubebuilder 认可的执行模式。Kubebuilder 通过 stdin 和 stdout 与这些插件进行交互，实现无缝通信。

为什么使用外部插件？

外部插件使第三方解决方案维护者能够将其工具与 Kubebuilder 集成。与 Kubebuilder 自身的插件类似，这些插件可以选择性使用，为用户提供工具选择的灵活性。通过在自己的代码库中开发插件，维护者确保更新与其 CI 流水线保持一致，并能够管理其责任范围内的任何变更。

如果您对这种类型的集成感兴趣，建议与第三方解决方案的维护者进行合作。Kubebuilder 的维护者始终乐意提供支持，以扩展其功能。

如何编写外部插件

Kubebuilder 与外部插件之间的通信通过标准输入/输出进行。可以使用任何语言创建插件，只要它遵循 PluginRequest 和 PluginResponse 结构。

PluginRequest包含从CLI收集的数据以及之前执行的插件。Kubebuilder通过stdin将这些数据作为JSON对象发送给外部插件。

Fields:

  • apiVersion：PluginRequest schema 的版本。
  • args：传递给插件的命令行参数。
  • command：正在执行的子命令（例如 init、create api、create webhook、edit）。
  • universe：文件路径到内容的映射，在插件链中更新。
  • pluginChain（可选）：按执行顺序列出的插件键数组。外部插件可检查此项，以便根据已运行的其他插件（例如 go.kubebuilder.io/v4 或 kustomize.common.kubebuilder.io/v2）调整行为。
  • config（可选）：当前项目的序列化 PROJECT 文件配置。用于检查元数据、现有资源或插件特定设置。在 PROJECT 文件存在之前——通常是第一次 init——Kubebuilder 会省略此字段，因此插件应检查其是否存在。

注意： 只要 Kubebuilder 可访问 PROJECT 文件（例如在 create api、create webhook、edit 或后续 init 运行期间），PluginRequest 就会包含 config 字段。在非常第一次 init 运行时该字段会被省略，因为 PROJECT 文件尚不存在。

示例 PluginRequest（通过 kubebuilder init --plugins sampleexternalplugin/v1 --domain my.domain 触发）：

{
  "apiVersion": "v1alpha1",
  "args": ["--domain", "my.domain"],
  "command": "init",
  "universe": {},
  "pluginChain": ["go.kubebuilder.io/v4", "kustomize.common.kubebuilder.io/v2", "sampleexternalplugin/v1"]
}

create api 的 PluginRequest 示例（包含 config）：

{
  "apiVersion": "v1alpha1",
  "args": ["--group", "crew", "--version", "v1", "--kind", "Captain"],
  "command": "create api",
  "universe": {},
  "pluginChain": ["go.kubebuilder.io/v4", "kustomize.common.kubebuilder.io/v2", "sampleexternalplugin/v1"],
  "config": {
    "domain": "my.domain",
    "repo": "github.com/example/my-project",
    "projectName": "my-project",
    "version": "3",
    "layout": ["go.kubebuilder.io/v4"],
    "multigroup": false,
    "resources": []
  }
}

示例 PluginRequest（通过 kubebuilder init --plugins sampleexternalplugin/v1 --domain my.domain 触发）：

{
  "apiVersion": "v1alpha1",
  "args": [],
  "command": "edit",
  "universe": {}
}

插件响应

PluginResponse 包含插件对项目所做的修改。该数据以 JSON 格式序列化，并通过 stdout 返回给 Kubebuilder。

示例 PluginResponse:

{
  "apiVersion": "v1alpha1",
  "command": "edit",
  "metadata": {
    "description": "`edit` 子命令会添加用于监控 operator 的 Prometheus 实例配置。",
    "examples": "kubebuilder edit --plugins sampleexternalplugin/v1"
  },
  "universe": {
    "config/prometheus/prometheus.yaml": "# Prometheus CR manifest...",
    "config/prometheus/kustomization.yaml": "resources:\n  - prometheus.yaml\n",
    "config/default/kustomization_prometheus_patch.yaml": "# Instructions for enabling Prometheus..."
  },
  "error": false,
  "errorMsgs": []
}

在你的外部插件中避免直接输出到 stdout。由于 Kubebuilder 和插件之间的通信是通过 stdin 和 stdout 使用结构化 JSON 进行的，任何意外的输出（例如调试日志）都可能导致错误。如果需要，请将日志写入文件。

如何使用外部插件

前提条件

  • Kubebuilder CLI 版本 > 3.11.0
  • 外部插件的可执行文件
  • 使用 ${EXTERNAL_PLUGINS_PATH} 或默认操作系统路径进行插件路径配置：
    • Linux: $HOME/.config/kubebuilder/plugins/${name}/${version}/${name}
    • macOS: ~/Library/Application Support/kubebuilder/plugins/${name}/${version}/${name}

示例： 对于在 Linux 上的插件 foo.acme.io 版本 v2，路径将是 $HOME/.config/kubebuilder/plugins/foo.acme.io/v2/foo.acme.io。

可用子命令

外部插件可以支持以下 Kubebuilder 子命令：

  • init: 项目初始化
  • create api: 创建 Kubernetes API 定义的脚手架
  • 创建 webhook: 创建 Kubernetes webhooks 的骨架
  • 编辑: 更新项目配置

可选子命令以增强用户体验：

  • metadata: 提供使用 --help 标志的插件描述和示例。
  • flags：通知Kubebuilder支持的标志，以便提前检测错误。

More about `flags` subcommand

外部插件中的 flags 子命令允许通过告知 Kubebuilder 插件支持的标志来提前进行错误检测。如果识别到不支持的标志，Kubebuilder 可以在调用插件执行之前发出错误。如果插件没有实现 flags 子命令，Kubebuilder 将把所有标志传递给插件，因此处理任何无效标志的责任将由外部插件承担。

配置插件路径

设置环境变量 $EXTERNAL_PLUGINS_PATH 以指定自定义插件二进制文件路径：

export EXTERNAL_PLUGINS_PATH=您训练的数据截至2023年10月。

否则，Kubebuilder 将根据您的操作系统在默认路径中搜索插件。

示例命令行指令

您现在可以通过调用 CLI 命令来使用它：

# 为现有项目添加 Prometheus 监控
kubebuilder edit --plugins sampleexternalplugin/v1

# 使用 Prometheus 监控更新现有项目
kubebuilder edit --plugins sampleexternalplugin/v1

# 显示 init 子命令的帮助信息
kubebuilder init --plugins sampleexternalplugin/v1 --help

# 显示 edit 子命令的帮助信息
kubebuilder edit --plugins sampleexternalplugin/v1 --help

# 插件链式示例：先使用 go/v4 插件，再应用外部插件
kubebuilder edit --plugins go/v4,sampleexternalplugin/v1
