单组到多组

Kubebuilder 默认脚手架单 group 项目以保持简单，因为多数项目不需要多个 API groups。但需要时，可将现有单 group 项目转换为多 group 布局。这会将 API 与 controllers 重组到按 group 划分的目录中。

此设计决策的理由见设计文档。

What's a Multi-Group Project?

当你为不同用途或领域构建 API 时，多 group 布局很有用。例如，你可能有：

  • 用于任务相关资源的 batch group（CronJob、Job）
  • 用于应用资源的 apps group（Deployment、StatefulSet）
  • 用于团队管理资源的 crew group（Captain、Sailor）

每个 group 有独立目录，随着项目增长保持组织清晰。

参见 Groups and Versions and Kinds, oh my! 以更好理解 API groups。

AI-Assisted Migration

此迁移涉及重复的文件移动与 import 路径更新。若使用 AI 编码助手，参见 AI 辅助迁移 获取即用说明。

理解布局

从单 group 到多 group 时会发生这些变化：

单 group 布局（默认）：

api/<version>/*_types.go                  All your CRD schemas in one place
internal/controller/*                     All your controllers together
internal/webhook/<version>/*              Webhooks organized by version (if you have any)

多 group 布局：

api/<group>/<version>/*_types.go          CRD schemas organized by group
internal/controller/<group>/*             Controllers organized by group
internal/webhook/<group>/<version>/*      Webhooks organized by group and version (if you have any)

可通过检查 PROJECT 文件中的 multigroup: true 判断当前布局。

迁移

下列步骤将 CronJob 示例 从单 group 迁移到多 group 布局。

Starting new projects with multigroup

若你在启动新项目时已知需要 multigroup 布局，可在初始化时使用 --multigroup 标志：

kubebuilder init --domain example.org --multigroup

本指南面向需要从单 group 迁移到多 group 布局的现有项目。

步骤 1：Enable multi-group mode

首先，告诉 Kubebuilder 你要使用多 group 布局：

kubebuilder edit --multigroup=true

该命令通过添加 multigroup: true 更新 PROJECT 文件。此变更之后：

  • 你创建的新 API 将自动使用多 group 结构（api/<group>/<version>/）
  • 现有 API 仍在当前位置，必须手动迁移（见下面步骤 3–9）

What this command changes

该命令会在 PROJECT 文件中添加或更新此行：

多组: true

此设置告诉 Kubebuilder 对所有后续脚手架操作使用基于 group 的目录。

步骤 2：Identify your group name

查看 api/v1/groupversion_info.go 以找到 group 名称：

// +组名=batch.tutorial.kubebuilder.io
package v1

Group 名称是点号前的第一部分（本例中为 batch）。

步骤 3：Move your APIs

为 group 创建目录并移动 version 目录：

mkdir -p api/batch
mv api/v1 api/batch/

若有多个版本（如 v1、v2 等），全部移动：

mv api/v2 api/batch/

步骤 4：Move your controllers

创建 group 目录并移动所有 controller 文件：

mkdir -p internal/controller/batch
mv internal/controller/*.go internal/controller/batch/

这会将包括 suite_test.go 在内的所有 controller 文件移入 group 目录。每个 group 需要自己的测试套件。

步骤 5：Move your webhooks (if you have any)

若项目有 webhooks（检查是否有 internal/webhook/ 目录），添加 group 目录：

mkdir -p internal/webhook/batch
mv internal/webhook/v1 internal/webhook/batch/
mv internal/webhook/v2 internal/webhook/batch/  # if v2 exists

如果您没有 webhook，可以跳过这一部分。

步骤 6：Update import paths

将所有 import 语句更新为指向新位置。

以前如下所示：

import (
    batchv1 "tutorial.kubebuilder.io/project/api/v1"
    "tutorial.kubebuilder.io/project/internal/controller"
)

现在应如下所示：

import (
    batchv1 "tutorial.kubebuilder.io/project/api/batch/v1"
    batchcontroller "tutorial.kubebuilder.io/project/internal/controller/batch"
)

若有 webhooks，还需要更新这些 imports：

// Before
webhookv1 "tutorial.kubebuilder.io/project/internal/webhook/v1"

// After
webhookbatchv1 "tutorial.kubebuilder.io/project/internal/webhook/batch/v1"

需要检查并更新的文件：

  • cmd/main.go
  • internal/controller/batch/*.go
  • internal/webhook/batch/v1/*.go（若有 Webhook）
  • api/batch/v1/*_test.go

提示：在整个项目中使用 IDE 的 “Find and Replace” 功能。

步骤 7：Update the PROJECT file

kubebuilder edit --multigroup=true 命令会在 PROJECT 文件中设置 multigroup: true，但不会更新现有 API 的路径。你需要手动更新每个资源的 path 字段。

验证你的 PROJECT 文件包含这些变更：

  1. 检查已设置 multigroup: true（在顶层）：
layout:
- go.kubebuilder.io/v4
多组: true  # Must be true
projectName: project
  1. 为每个资源更新 path 字段：

Before:

resources:
- api:
    crdVersion: v1
    namespaced: true
  controller: true
  group: batch
  kind: CronJob
  path: tutorial.kubebuilder.io/project/api/v1  # 旧路径
  version: v1

After:

resources:
- api:
    crdVersion: v1
    namespaced: true
  controller: true
  group: batch
  kind: CronJob
  path: tutorial.kubebuilder.io/project/api/batch/v1  # 带 group 的新路径
  version: v1

对 PROJECT 文件中的所有资源重复此操作。

步骤 8：Update test suite CRD paths

更新测试套件中的 CRD 目录路径。由于文件下移了一层，路径需再加一层 ".."。

在 internal/controller/batch/suite_test.go 中：

之前（位于 internal/controller/suite_test.go）：

testEnv = &envtest.Environment{
    CRDDirectoryPaths: []string{filepath.Join("..", "..", "config", "crd", "bases")},
}

之后（现位于 internal/controller/batch/suite_test.go）：

testEnv = &envtest.Environment{
    CRDDirectoryPaths: []string{filepath.Join("..", "..", "..", "config", "crd", "bases")},
}

若有 webhooks，更新 internal/webhook/batch/v1/webhook_suite_test.go：

之前（位于 internal/webhook/v1/webhook_suite_test.go）：

testEnv = &envtest.Environment{
    CRDDirectoryPaths: []string{filepath.Join("..", "..", "..", "config", "crd", "bases")},
}

之后（现位于 internal/webhook/batch/v1/webhook_suite_test.go）：

testEnv = &envtest.Environment{
    CRDDirectoryPaths: []string{filepath.Join("..", "..", "..", "..", "config", "crd", "bases")},
}

步骤 9：Verify the migration

运行下列命令验证一切正常：

make manifests      # Regenerate CRDs and RBAC
make generate       # Regenerate code
make test           # Run tests
make build          # Build the project

AI 辅助迁移

若使用 AI 编码助手（Cursor、GitHub Copilot 等），可自动化大部分迁移步骤。

AI Migration Instructions

Prerequisites:

  1. 首先，从 api/v1/groupversion_info.go 确认 API group 名称（查找 +groupName=<group>.<domain>）
  2. 从 go.mod 获取模块路径（第一行：module <repo>）

提供给 AI 助手的说明：

将这些说明给你的 AI 助手，并替换前两行中的值：

I need to migrate this Kubebuilder project to multi-group layout.

Project details:
- Group name: batch
- Module path: tutorial.kubebuilder.io/project

Context:
Kubebuilder projects have three main code locations:
- api/<version>/ - Contains CRD type definitions (*_types.go files)
- internal/controller/ - Contains reconcilers (*_controller.go files)
- internal/webhook/<version>/ - Contains webhooks (*_webhook.go files) [if present]

Multi-group layout reorganizes these into group-specific directories:
- api/<group>/<version>/ - Types organized by API group
- internal/controller/<group>/ - Controllers organized by group
- internal/webhook/<group>/<version>/ - Webhooks organized by group

This keeps code organized as projects grow to support multiple API groups.

References:
- Kubebuilder Book: ../introduction.md

Steps to execute:

1. Enable multi-group mode:
   Run: kubebuilder edit --multigroup=true

2. Move API files:
   mkdir -p api/batch
   mv api/v1 api/batch/
   mv api/v2 api/batch/  # if v2 exists

3. Move controller files:
   mkdir -p internal/controller/batch
   mv internal/controller/*.go internal/controller/batch/

4. Move webhook version directories (ONLY if internal/webhook/ exists):
   # Skip this step entirely if you do not have an internal/webhook/ directory
   if [ -d "internal/webhook" ]; then
     mkdir -p internal/webhook/batch
     mv internal/webhook/v1 internal/webhook/batch/ 2>/dev/null || true
     mv internal/webhook/v2 internal/webhook/batch/ 2>/dev/null || true
   fi

5. Update all import paths:
   - In cmd/main.go, internal/controller/batch/*.go, api/batch/*/*.go (and webhook files if they exist)
   - Replace: tutorial.kubebuilder.io/project/api/v1 -> tutorial.kubebuilder.io/project/api/batch/v1
   - Replace: tutorial.kubebuilder.io/project/api/v2 -> tutorial.kubebuilder.io/project/api/batch/v2
   - Replace: tutorial.kubebuilder.io/project/internal/controller -> tutorial.kubebuilder.io/project/internal/controller/batch
   - If you have webhooks, also replace:
     tutorial.kubebuilder.io/project/internal/webhook/v1 -> tutorial.kubebuilder.io/project/internal/webhook/batch/v1
     tutorial.kubebuilder.io/project/internal/webhook/v2 -> tutorial.kubebuilder.io/project/internal/webhook/batch/v2

6. Update PROJECT file:
   - Verify multigroup: true is set (should be set by step 1)
   - For each resource entry, update the path field
   - From: tutorial.kubebuilder.io/project/api/v1
   - To: tutorial.kubebuilder.io/project/api/batch/v1
   - Example:
     ```yaml
     layout:
     - go.kubebuilder.io/v4
     multigroup: true  # This must be true
     resources:
     - api:
         crdVersion: v1
         namespaced: true
       controller: true
       domain: tutorial.kubebuilder.io
       group: batch
       kind: CronJob
       path: tutorial.kubebuilder.io/project/api/batch/v1  # Updated path
       version: v1
     ```

7. Fix test suite CRD paths (add one more ".."):
   - In internal/controller/batch/suite_test.go:
     From: filepath.Join("..", "..", "config", "crd", "bases")
     To: filepath.Join("..", "..", "..", "config", "crd", "bases")
   - If you have webhooks, also in internal/webhook/batch/v1/webhook_suite_test.go:
     From: filepath.Join("..", "..", "..", "config", "crd", "bases")
     To: filepath.Join("..", "..", "..", "..", "config", "crd", "bases")

8. Verify:
   Run: make manifests && make generate && make test

AI 完成后：

  • 仔细审查变更
  • 验证 import 路径正确
  • 检查 PROJECT 文件路径
  • 运行 make test 以发现任何问题
