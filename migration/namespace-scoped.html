迁移到命名空间作用域 Manager

本指南介绍如何将现有集群作用域项目转换为 Namespace 作用域部署。

Creating New Namespace-Scoped Projects

如果正在创建新项目，只需使用：

kubebuilder init --domain example.com --namespaced

包括 cmd/main.go 与 RBAC 配置在内的所有文件都会正确脚手架。用 kubebuilder create api 创建的所有 controllers 会在 RBAC markers 中自动带有 namespace= 参数。无需手动更改或迁移步骤。

默认情况下，Kubebuilder 脚手架集群作用域的 managers，可监视并管理所有 namespaces 中的资源。本指南说明如何将现有集群作用域项目转换为 Namespace 作用域部署，使 manager 仅监视特定 namespace(s)。

何时使用命名空间作用域

在以下情况使用命名空间作用域：

  • 在多租户集群中构建租户专用 managers
  • 安全策略要求最小权限（无集群范围权限）
  • 需要在不同 namespaces 中运行多个 manager 实例
  • 仅管理 Namespace 作用域资源（Deployments、Services、ConfigMaps 等）

在以下情况使用集群作用域（默认）：

  • 管理集群作用域资源（Nodes、ClusterRoles、Namespaces 等）
  • 单个 manager 实例管理所有 namespaces 中的资源

AI-Assisted Migration

此迁移涉及更新多个 controller 文件中的 RBAC markers。若使用 AI 编码助手，参见 AI 辅助迁移 获取即用说明。

迁移

快速摘要：

  1. 运行 kubebuilder edit --namespaced --force — 脚手架 Role/RoleBinding 并更新 manager.yaml
  2. 更新 cmd/main.go 以配置 Namespace 作用域缓存
  3. 在现有 controller 文件的 RBAC markers 中添加 namespace= 参数
  4. 运行 make manifests — 根据更新后的 markers 重新生成 RBAC
  5. 验证并部署

Manual Steps Required

edit 命令会自动脚手架 RBAC 文件并更新 manager.yaml（配合 --force），但无法更新现有 controller 文件或 cmd/main.go。

你必须手动更新：

  • cmd/main.go 命名空间作用域缓存配置
  • 现有控制器的 RBAC 标记

注意： 启用 namespaced 模式后创建的新 controllers 会自动带有正确的 RBAC markers。

详细步骤

1. 启用命名空间作用域模式

kubebuilder edit --namespaced --force

该命令会自动：

  • 在 PROJECT 文件中设置 namespaced: true
  • 脚手架 kind: Role（Namespace 作用域）的 config/rbac/role.yaml
  • 脚手架 kind: RoleBinding 的 config/rbac/role_binding.yaml
  • 重新生成带有 WATCH_NAMESPACE 环境变量的 config/manager/manager.yaml
  • 为所有现有 API 重新生成 kind: Role（Namespace 作用域）的 admin/editor/viewer roles

注意： --force 标志会重新生成 config/manager/manager.yaml。不带 --force 时，必须手动添加 WATCH_NAMESPACE（见下文）。

2. 更新 cmd/main.go（必需的手动步骤）

edit 命令无法自动更新 cmd/main.go。你必须手动添加 Namespace 作用域配置。

a. 添加 import：

import (
    // ... 现有导入 ...
    "sigs.k8s.io/controller-runtime/pkg/cache"
)

b. 添加辅助函数（在 init() 之后、main() 之前）：

// getWatchNamespace 返回 Manager 应监视变更的命名空间。
// 它从 WATCH_NAMESPACE 环境变量读取该值。
func getWatchNamespace() (string, error) {
    watchNamespaceEnvVar := "WATCH_NAMESPACE"
    ns, found := os.LookupEnv(watchNamespaceEnvVar)
    if !found {
        return "", fmt.Errorf("%s must be set", watchNamespaceEnvVar)
    }
    return ns, nil
}

// setupCacheNamespaces 配置缓存以监视特定命名空间。
func setupCacheNamespaces(namespaces string) cache.Options {
    defaultNamespaces := make(map[string]cache.Config)
    for _, ns := range strings.Split(namespaces, ",") {
        defaultNamespaces[strings.TrimSpace(ns)] = cache.Config{}
    }
    return cache.Options{
        DefaultNamespaces: defaultNamespaces,
    }
}

c. 在 main() 函数中，于 ctrl.NewManager() 之前添加：

// 从 WATCH_NAMESPACE 环境变量获取命名空间作用域模式的命名空间。
watchNamespace, err := getWatchNamespace()
if err != nil {
    setupLog.Error(err, "Unable to get WATCH_NAMESPACE")
    os.Exit(1)
}

d. 更新 manager 创建以使用 Namespace 作用域缓存：

mgrOptions := ctrl.Options{
    Scheme:                 scheme,
    Metrics:                metricsServerOptions,
    WebhookServer:          webhookServer,
    HealthProbeBindAddress: probeAddr,
    LeaderElection:         enableLeaderElection,
    LeaderElectionID:       "your-leader-election-id",
    // ... other existing options ...
}

// 配置缓存以监视 WATCH_NAMESPACE 中指定的命名空间
mgrOptions.Cache = setupCacheNamespaces(watchNamespace)
setupLog.Info("Watching namespace(s)", "namespaces", watchNamespace)

mgr, err := ctrl.NewManager(ctrl.GetConfigOrDie(), mgrOptions)
if err != nil {
    setupLog.Error(err, "Failed to start manager")
    os.Exit(1)
}

If You Didn't Use --force

若运行 kubebuilder edit --namespaced 时未加 --force，请手动将 WATCH_NAMESPACE 添加到 config/manager/manager.yaml：

spec:
  template:
    spec:
      容器:
      - name: manager
        env:
        - name: WATCH_NAMESPACE
          valueFrom:
            fieldRef:
              字段路径: metadata.namespace

使用 --force 时会自动完成。若已用 --force 可跳过。

3. 更新现有控制器中的 RBAC 标记

对每个现有 controller 文件，在 RBAC markers 中添加 namespace= 参数。

查找控制器文件：

  • 查找包含 func (r *SomeReconciler) Reconcile( 的文件
  • 常见位置：internal/controller/*_controller.go

在 internal/controller/cronjob_controller.go 中：

之前（集群作用域）：

// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,resources=cronjobs,verbs=get;list;watch;create;update;patch;delete
// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,resources=cronjobs/status,verbs=get;update;patch
// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,resources=cronjobs/finalizers,verbs=update

// Reconcile 是主 Kubernetes 协调循环的一部分
func (r *CronJobReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {

之后（命名空间作用域）：

// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,namespace=<project-name>-system,resources=cronjobs,verbs=get;list;watch;create;update;patch;delete
// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,namespace=<project-name>-system,resources=cronjobs/status,verbs=get;update;patch
// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,namespace=<project-name>-system,resources=cronjobs/finalizers,verbs=update

// Reconcile 是主 Kubernetes 协调循环的一部分
func (r *CronJobReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {

将 project-system 替换为你的 namespace（在 config/default/kustomization.yaml 的 namespace: 字段中）。

New Controllers Get This Automatically

运行 kubebuilder edit --namespaced --force 后，新创建的 controllers 会自动带有 namespace= 参数：

kubebuilder create api --group myapp --version v1 --kind MyNewKind --controller=true --resource=true

生成的控制器将包含：

// +kubebuilder:rbac:groups=myapp.example.com,namespace=<project-name>-system,resources=mynewkinds,verbs=...

只有现有控制器需要手动更新！

4. 重新生成 RBAC 清单

在步骤 3 更新 RBAC markers 后，重新生成 RBAC manifests：

make manifests      # Regenerate RBAC from updated controller markers

确认生成的文件显示 kind: Role 而非 kind: ClusterRole：

config/rbac/role.yaml:

kind: Role
metadata:
  name: manager-role
  # 注意：命名空间由 kustomize 在构建时添加，不在源文件中

**config/rbac/*_editor_role.yaml, _viewer_role.yaml, _admin_role.yaml:

kind: Role
metadata:
  name: cronjob-editor-role
  # 注意：命名空间由 kustomize 在构建时添加，不在源文件中

Metrics Auth Role Stays Cluster-Scoped

config/rbac/metrics_auth_role.yaml 将保持为 kind: ClusterRole — 这是正确的。Metrics 认证使用集群作用域 API（TokenReview、SubjectAccessReview），即使在 Namespace 作用域项目中也必须保持集群作用域。

5. 验证并部署

运行测试以验证一切正常：

make generate       # Regenerate code
make test           # Run tests

部署并验证：

make deploy IMG=<your-image>

# Verify RBAC is namespace-scoped (not cluster-scoped)
kubectl get role,rolebinding -n <manager-namespace>

# Test: Create a resource in the manager's 命名空间 - 应被协调
kubectl apply -f config/samples/ -n <manager-namespace>

# 测试：在不同命名空间中创建资源 - 不应被协调
kubectl apply -f config/samples/ -n other-namespace

Webhooks and Namespace-Scoped Mode

若项目有 webhooks，manager 缓存受限于 WATCH_NAMESPACE，但 webhooks 默认仍接收来自所有 namespaces 的请求。

问题：

Webhook 服务器会接收来自所有 namespaces 的 admission 请求，但缓存仅有 WATCH_NAMESPACE 的数据。若 webhook handler 查询监视范围外对象的缓存，查找会失败。

Solution:

在 webhooks 上配置 namespaceSelector 或 objectSelector，使 webhook 作用域与缓存一致。目前 controller-gen 尚无对应 markers。必须用 Kustomize patches 手动添加。

创建并应用 namespace selector patches 的详细步骤见 Webhook Bootstrap 问题 指南。

   Important: Only update RBAC markers in controller files (files containing "Reconcile" function).
   Do not modify webhook files (files in internal/webhook/ or api/*/webhook.go).

   - Add namespace=<value-from-kustomization> parameter to each marker

   // +kubebuilder:rbac:groups=myapp.example.com,resources=mykinds/finalizers,verbs=update

   After:
   // +kubebuilder:rbac:groups=myapp.example.com,namespace=<value-from-kustomization>,resources=mykinds,verbs=get;list;watch;create;update;patch;delete

多命名空间支持

WATCH_NAMESPACE 环境变量支持逗号分隔的值，以监视多个特定 namespaces：

env:
- name: WATCH_NAMESPACE
  value: "namespace-1,namespace-2,namespace-3"

注意：需要在每个 namespace 中创建 Role/RoleBinding 才能有正确的 RBAC。

恢复为集群作用域

恢复为集群作用域：

kubebuilder edit --namespaced=false --force

该命令会自动：

  • 在 PROJECT 文件中设置 namespaced: false
  • 脚手架 kind: ClusterRole 的 config/rbac/role.yaml
  • 脚手架 kind: ClusterRoleBinding 的 config/rbac/role_binding.yaml
  • 使用 --force：重新生成不含 WATCH_NAMESPACE 环境变量的 config/manager/manager.yaml

需要手动执行的步骤：

  1. 从所有 controller 文件的 RBAC markers 中移除 namespace= 参数
  2. 运行 make manifests 重新生成集群作用域 RBAC
  3. 从 cmd/main.go 中移除命名空间作用域代码：
    • 移除 getWatchNamespace() 函数
    • 移除 setupCacheNamespaces() 函数
    • 移除命名空间获取与缓存配置
    • 若别处未使用，移除新增的 imports（fmt、strings、cache）
  4. 若未使用 --force，请手动从 config/manager/manager.yaml 移除 WATCH_NAMESPACE

重要说明

  • 仅 controllers 需要更新 RBAC：只更新 controller 文件（含 Reconcile 函数的文件）中的 +kubebuilder:rbac markers。Webhook 文件不使用 RBAC markers——webhooks 使用基于证书的认证与 API server 通信。
  • RBAC markers 控制作用域：controller RBAC markers 中的 namespace= 参数决定 controller-gen 生成 Role（Namespace 作用域）还是 ClusterRole（集群作用域）。没有 namespace= 参数时，controller-gen 始终生成 ClusterRole。
  • Controller-gen 会重新生成 role.yaml：运行 make manifests 后，controller-gen 会根据 controller RBAC markers 重新生成 config/rbac/role.yaml。kubebuilder edit --namespaced=true 初始脚手架的 Role 作为模板，但实际内容由 controller-gen 管理。
  • Namespace 参数格式：在 controller RBAC markers 中使用 namespace=<your-namespace>，通常为 namespace=<project-name>-system 以匹配部署 namespace。
  • Metrics auth role 保持集群作用域：metrics-auth-role 使用集群作用域 API（TokenReview、SubjectAccessReview），正确地保持为无 namespace 参数的 ClusterRole。
  • Webhooks 需要手动配置：目前 controller-gen 不支持 webhooks 的 namespaceSelector 或 objectSelector markers。详见上文 webhook 部分。
